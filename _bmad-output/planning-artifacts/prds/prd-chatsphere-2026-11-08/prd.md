# ChatSphere — 产品需求文档（PRD）

## 1. 概述与目标

ChatSphere 是一款可嵌入任意网站或 App 的自托管实时社区聊天系统，通过单个 `<script>` 标签部署，数据完全归属于站长自己的服务器。

**产品目标（v1）**
- 让任何站长在 30 分钟内完成安装，并将实时社区聊天嵌入自己的网站
- 访客无需注册即可匿名聊天；注册用户获得更丰富的社交功能
- 管理员通过后台完整管控频道、消息、用户和内容审核
- 支持自托管买断授权和未来云托管订阅两种交付方式

**v1 不包含**
- 文件/图片上传
- 云托管 SaaS 版本（架构预留，不交付）
- 移动原生 SDK
- 邮件通知（@ 提及仅在 widget 内通知）

---

## 2. 用户角色

| 角色 | 定义 |
|------|------|
| **访客（匿名用户）** | 无需注册，以 IP 哈希生成稳定匿名身份，可立即参与聊天 |
| **注册用户** | 账号体系，解锁私信、@ 提及通知、声誉积分、身份徽章 |
| **频道版主（Moderator）** | 可删除消息、处理举报，权限限于所管理的频道 |
| **管理员（Admin）** | 完整后台权限：频道 CRUD、用户封禁、机器人配置、全局设置 |

## 3. 核心用户旅程

### UJ-1：访客首次使用 Widget
**主角：** 阿明，影视站的访客，第一次看到页面右下角的悬浮聊天框。

1. 页面加载，ChatSphere widget 以动画方式出现在右下角，显示频道名、在线人数。
2. 阿明点击展开，看到其他影迷正在讨论最新一集剧情，消息包含国旗和声誉徽章。
3. 阿明直接在输入框打字，以"访客_AZ1"的匿名名称发出消息，无需任何注册步骤。
4. 阿明看到自己的消息出现在对话流中，其他人的回复实时滚动进来。
5. 阿明决定注册以获得固定名字，点击"登录/注册"按钮，在 widget 内完成注册，不跳转页面。

**成功条件：** 阿明从打开 widget 到发出第一条消息 < 10 秒，全程不离开当前页面。

---

### UJ-2：注册用户被 @ 提及
**主角：** 小林，常驻注册用户，不在活跃聊天中。

1. 另一位用户在聊天中输入 `@小林 你看了最新一集吗？`，消息发出。
2. Widget 折叠状态下，小林的头像旁出现红色数字角标（未读提及数）。
3. 小林的设备播放一声轻微的提示音（可在设置中关闭）。
4. 小林点击展开 widget，消息列表自动滚动到包含 @ 的消息，该消息高亮显示。
5. 小林回复，@ 通知角标清零。

**成功条件：** 提及通知在消息发出后 < 2 秒内呈现给被 @ 的用户。

---

### UJ-3：管理员首次安装
**主角：** Kevin，站长，第一次在服务器上运行 ChatSphere。

1. Kevin 执行 `./chatsphere`，浏览器自动跳转至安装向导页面（:8080/setup）。
2. Kevin 在步骤一输入 MySQL 连接信息，点击"测试连接"，界面显示"连接成功"绿色徽章。
3. Kevin 完成 Redis 连接测试、创建管理员账号、填写站点名称和默认频道名称。
4. 点击"完成安装"，向导显示进度日志（建表、创建管理员、生成配置文件），安装完成后服务器自动切换到正常运行模式。
5. Kevin 进入管理后台，在"Widget 嵌入"页面复制一行 `<script>` 代码，粘贴到自己网站的 HTML 中。

**成功条件：** 从启动二进制到 widget 上线 < 30 分钟，无需手动编辑任何配置文件。

## 4. 功能需求

### F1 — 嵌入 Widget

**FR-1.1** Widget 通过单个 `<script>` 标签嵌入，支持以下 `data-*` 属性配置：`data-server`（服务器地址）、`data-channel`（频道 slug）、`data-position`（`bottom-left` / `bottom-right`）、`data-title`、`data-notice`。

**FR-1.2** 支持 `window.ChatSphere.init(opts)` 手动初始化 API，参数与 `data-*` 属性对应；支持 `ChatSphere.setTitle()`、`ChatSphere.setNotice()` 运行时方法。

**FR-1.3** Widget 所有 CSS 样式以 `[data-cs="root"]` 为根作用域，不与宿主页面样式产生冲突。

**FR-1.4** Widget 支持折叠/展开两种状态；折叠时在角标显示未读消息数量。

**FR-1.5** Widget 展开后展示频道头部（标题、在线人数）、消息列表、输入区域；支持"侧边栏"展开模式显示社区规则和在线用户统计。

**FR-1.6** 输入区域提供 emoji 选择器（≥30 种常用表情），支持浏览器 Speech Recognition API 语音输入（有麦克风权限时显示语音按钮）。

**FR-1.7** 每条消息展示：发送者国旗（基于 IP 地理位置）、声誉徽章（由管理员分配的积分段）、匿名/注册标识。

**FR-1.8** 注册用户可对消息进行举报，举报后消息对举报者本地隐藏，举报进入管理后台待处理队列。

---

### F2 — 用户系统

**FR-2.1** 匿名用户以 SHA-256(IP + 盐) 生成稳定哈希身份，显示名以"形容词+名词"组合生成（如 "Swift Hawk"），同一 IP 在同一频道名称稳定。

**FR-2.2** 注册接口接受用户名（唯一）、密码（bcrypt 哈希）、邮箱（可选）；登录返回 30 天有效期 JWT。

**FR-2.3** 登录/注册流程在 widget 内以覆盖层形式完成，不跳转页面。

**FR-2.4** 用户 profile 包含：用户名、头像颜色（由用户名哈希确定，12 色调色板）、所在国家（基于 IP）、声誉积分（管理员可调整）、角色（admin / moderator / member）、封禁状态、最后在线时间。声誉积分以**颜色徽章**形式展示，默认分段规则为：0（无徽章）/ 10+（铜）/ 50+（银）/ 100+（金）；管理员可在后台自定义积分段阈值、徽章颜色和标签文案。

**FR-2.5（@ 提及）** 用户在消息中输入 `@用户名` 时：
- 被提及用户的 widget 在折叠状态显示红色提及计数角标
- 收到浏览器声音提示（默认使用内置音效，默认开启，用户可关闭）；管理员可在后台上传自定义音效文件替换默认音效
- 展开 widget 后，包含 @ 的消息高亮显示，列表自动滚动至该消息
- 提及计数在用户查看对应消息后清零

**FR-2.6（私信）** 注册用户可对其他注册用户发起私信：
- 私信入口在消息列表的用户名旁显示（点击触发）
- 私信以**浮层抽屉**形式从 widget 侧边划入展示，不替换频道聊天视图，可随时滑回
- 收到私信时在 widget 角标叠加提示数字
- 私信消息持久化到 MySQL；管理员可在后台设置中开启**端对端加密开关**：关闭时服务端明文存储；开启时采用客户端加密，服务端仅存储密文

---

### F3 — 多频道

**FR-3.1** 管理员可创建任意数量频道，每个频道有独立的 slug（URL 路径标识符，唯一）。

**FR-3.2** 频道配置项：名称、slug、描述、是否为默认频道、是否启用、最大消息长度（字符数）、发言速率限制（秒/次）、是否允许匿名用户、欢迎消息、Telegram 社群链接（可选）。

**FR-3.3** 每个频道独立维护：Redis 最近 500 条消息缓存（24h TTL）+ MySQL 永久持久化；新用户连接时推送历史记录。

**FR-3.4** 频道在线人数通过 Redis 维护，实时更新，显示在 widget 头部。

**FR-3.5** 单个频道应支持数百并发连接（v1 基线），服务端架构采用无状态设计以支持未来水平扩展至千级/万级并发。

---

### F4 — 安装向导

**FR-4.1** 启动时检测 `config.yaml` 是否存在；若不存在，HTTP 服务在 `:8080/setup` 提供安装向导，阻塞正常服务启动。

**FR-4.2** 向导分步骤完成（至少包含）：
1. 数据库配置与连接测试：分字段填写（地址、端口、账号、密码、数据库名），点击「测试连接」显示成功/失败徽章及错误原因
2. Redis 配置与连接测试：分字段填写（地址、端口、密码、库编号），同样提供连接测试
3. 管理员账号创建（用户名 + 密码 + 密码确认）
4. 站点基本信息（站点名、默认频道名、管理后台路径）

**FR-4.3** 安装完成后自动在指定路径生成 `config.yaml`，每个配置项附带中英文注释说明用途和可选值。

**FR-4.4** 安装完成后服务自动切换到正常运行模式，无需重启进程；向导前端显示实时安装日志（建表、创建管理员、生成配置文件等步骤）。

**FR-4.5** 若 `config.yaml` 存在但连接失败（数据库/Redis 不可达），服务启动时返回明确错误信息，不静默失败。

---

### F5 — 管理后台

**FR-5.1（Dashboard）** 首页展示实时统计：总在线用户数、今日消息数、活跃频道数、待处理举报数。

**FR-5.2（频道管理）** 频道列表，支持新建、编辑、启用/停用频道；编辑面板覆盖 FR-3.2 中全部配置项。

**FR-5.3（消息管理）** 消息列表支持按频道、关键词、用户名、时间范围筛选；支持单条和批量软删除（在 widget 侧隐藏，不物理删除）。

**FR-5.4（用户管理）** 用户列表支持搜索；对单个用户可执行：封禁/解封（封禁用户无法发言）、调整声誉积分、查看历史消息。

**FR-5.5（举报管理）** 举报列表按状态分标签页（待处理 / 已处理 / 已忽略）；每条举报关联原始消息；支持一键删除消息并标记举报为已处理，或直接忽略。

**FR-5.6（Widget 嵌入生成器）** 提供可视化配置界面（服务器地址、频道、位置），实时生成可复制的 `<script>` 嵌入代码片段。

**FR-5.7（机器人与审核规则）** 见 F6。

**FR-5.8（Widget 主题自定义）** 管理员在 Settings → Widget 主题页面可修改 Widget 强调色（accent color）：
- 提供颜色选择器（原生 `<input type="color">`）
- 页面内嵌实时 Widget 预览，颜色变化 < 100ms 反映在预览中
- 可自定义的 token：`--accent`（强调色）；`--accent-dim` 和 `--accent-glow` 由系统根据 `--accent` 自动计算（透明度变体）
- 保存后服务端生成内联 CSS 片段，注入 Widget 初始化脚本；新访客立即生效，已连接客户端下次刷新后生效
- v1 不开放背景色和边框色自定义

---

### F6 — 审核机器人（Moderation Bot）

**FR-6.1** 管理员可在后台为每个频道配置屏蔽词列表；同时支持**精确匹配**（普通字符串）和**正则表达式**（以 `/` 包裹标识，如 `/bad\w+/i`）两种规则类型，可混合使用。

**FR-6.2** 当用户消息命中屏蔽词时，消息自动被拦截，不发布到频道；Bot 以系统消息的形式在频道内发出简短提示（如"该消息因包含违禁词已被过滤"）。

**FR-6.3** Bot 以固定系统用户身份（`ChatSphere Bot`）出现在消息流中，有专属头像标识，不可被普通用户 @ 或私信。

**FR-6.4** 命中拦截的消息在管理后台消息列表中可见（标注为"已过滤"），管理员可选择恢复或永久删除。

**FR-6.5** 速率限制（`rate_limit_seconds` 频道配置）由服务端 WebSocket 层强制执行，超限消息直接丢弃并向客户端返回提示。

---

### F7 — Widget 多语言

**FR-7.1** Widget 所有面向用户的 UI 文案（按钮、占位符、系统提示、时间戳格式等）支持通过 `data-lang` 属性或 `init()` 参数指定语言。

**FR-7.2** 默认语言为英文（`en`）；v1 内置简体中文（`zh-CN`）预置翻译包。

**FR-7.3** 支持完全自定义文案覆盖：`init({ labels: { sendButton: "发送", anonymousName: "匿名访客", ... } })`，任意 key 可单独覆盖，未覆盖的 key 回退到所选语言默认值。

**FR-7.4** 额外语言（繁中 `zh-TW`、日文 `ja`、西班牙文 `es` 等）以社区贡献方式在后续版本添加；v1 只交付 `en` 和 `zh-CN`，翻译文件结构设计为可扩展格式以便社区 PR 贡献。

## 5. 非功能需求

**NFR-1 性能**
- 单频道支持 500 个并发 WebSocket 连接（v1 基线）
- 消息端到端延迟（发送到其他客户端收到）< 200ms p95（同地区部署）
- Widget JS 文件加载 < 50ms（gzip 压缩后目标 < 30KB）
- 管理后台页面首次加载 < 2s（本地网络）

**NFR-2 可靠性**
- 应用层无状态设计，支持水平扩展（多实例部署共享同一 MySQL + Redis）
- WebSocket 断开后客户端自动重连（指数退避，最大间隔 30s）
- 服务进程支持优雅关闭（SIGTERM），等待活跃连接处理完成后退出

**NFR-3 安全**
- 所有 API 端点（除 WebSocket 和公开频道列表外）需 JWT 鉴权
- 管理后台路径可自定义（`admin.path` 配置项），避免路径可预测
- 消息内容在存储前进行 HTML 转义，防止 XSS
- 匿名用户 IP 以 SHA-256 + 随机盐哈希后存储，不保存原始 IP
- JWT 密钥在安装向导时由服务端 `crypto/rand` 自动生成，写入 `config.yaml`；`config.yaml` 不应提交到版本控制，文档中明确说明

**NFR-4 部署**
- 提供 Docker Compose 一键部署（app + MySQL + Redis）
- 单二进制文件，web 静态资源以 `go:embed` 打包，无外部文件依赖
- 支持反向代理（Nginx / Caddy）部署，配置文档提供示例

## 7. 成功指标

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 安装成功率 | 新用户安装向导完成率 > 90% | 向导步骤完成日志 |
| 安装耗时 | 从启动到 widget 上线 ≤ 30 分钟 | 用户测试计时 |
| Widget 性能 | 宿主页面 Lighthouse 性能分不因嵌入下降 > 5 分 | Lighthouse 对比测试 |
| 消息延迟 | p95 < 200ms（同地区） | WebSocket 时间戳差值 |
| 举报处理 | 管理员可在 3 次操作内完成一条举报的处理 | 可用性测试 |

**反向指标（不应发生）**
- Widget 加载导致宿主页面 JS 报错
- 管理后台路径泄露敏感信息（即使未登录也不应 500）
- 安装向导因连接失败进入不可恢复状态
